# 739. 每日温度

- 算法分类：单调栈。
- 数据结构：数组、存储下标的栈。
- 对应代码：[739_daily_temperatures.cpp](./739_daily_temperatures.cpp)。
- 练习状态：`dailyTemperatures` 已完成，12 组固定测例全部通过。

## 题意

给定每天的温度数组 `temperatures`，计算每一天还要等待多少天，才能遇到**严格更高**的温度。
如果之后没有更高的温度，该天的答案为 `0`。
结果是等待的天数，也就是两个下标的差，不是温度差。

例如 `[73, 74, 75, 71, 69, 72, 76, 73]` 的答案为 `[1, 1, 4, 2, 1, 1, 0, 0]`。
下标 `2` 的温度是 `75`，下标 `6` 才首次出现更高温度 `76`，因此等待 `6 - 2 = 4` 天。

## 单调栈思路

从左向右扫描，用栈保存“尚未找到更高温度”的日期下标。
从栈底到栈顶，对应温度保持**非递增**，允许相等；下标则严格递增。
栈中存下标，既能通过数组查询温度，也能在找到答案时计算等待天数。

处理当前下标 `i` 时：

1. 如果栈不为空，且当前温度严格高于栈顶下标对应的温度，则当前日解决了栈顶那一天的等待。
2. 取出该下标 `j`，将它的答案记录为 `i - j`，并弹出栈顶。
3. 继续检查新的栈顶，直到栈为空或当前温度不再严格更高。
4. 将当前下标 `i` 入栈，等待未来的更高温度。

答案数组预先全部初始化为 `0`。扫描结束后，栈中剩余日期都没有更高温度，保留 `0` 即可。
这里的连续弹栈需要使用循环：某一天可能同时成为此前多个日期的第一个更暖日。

## 为什么得到的是第一个更暖日

假设下标 `j` 直到处理 `i` 时才被弹出。
如果 `j` 和 `i` 之间已经出现过比 `temperatures[j]` 更高的温度，扫描到那一天时就会弹出 `j`。
因为 `j` 上方的温度都不高于它，更高的当前温度会先弹出这些元素，再弹出 `j`。
所以实际弹出 `j` 的下标 `i`，正是右侧第一个严格更高温度的位置。

## 边界与易错点

- 相同温度不算更暖，比较条件应是严格大于；`[70, 70, 71]` 的答案为 `[2, 1, 0]`。
- 栈里存下标，而不是只存温度，否则无法直接计算等待天数。
- 访问栈顶前必须先判断栈不为空。
- 一次扫描可能需要弹出多个元素，不能只用一次 `if` 处理栈顶。
- 弹栈时填写旧下标 `j` 的答案，不是当前下标 `i` 的答案。
- 当前下标应在处理完旧栈顶后入栈，避免它自身挡住需要比较的日期。
- 单元素、全部相同、严格递减的数组，其答案都全部为 `0`。
- 最后一天必然没有后续日期，答案为 `0`。

## 复杂度

- 时间复杂度：`O(n)`。每个下标最多入栈一次、出栈一次，内层循环的总弹栈次数不超过 `n`，均摊到每个元素是 `O(1)`。
- 辅助空间复杂度：`O(n)`，最坏情况下所有日期都留在栈中。
- 返回的答案数组另占 `O(n)` 空间；若将其计入，总额外空间仍为 `O(n)`。
