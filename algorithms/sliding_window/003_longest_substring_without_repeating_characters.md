# 3. 无重复字符的最长子串

- 算法分类：滑动窗口、双指针。
- 数据结构：哈希表 `unordered_map<char, int>`。
- 对应代码：[003_longest_substring_without_repeating_characters.cpp](./003_longest_substring_without_repeating_characters.cpp)。

## 题意

给定字符串 `s`，求不含重复字符的最长**连续子串**的长度。
子串必须连续，不能跳过字符拼接；例如 `pwwkew` 的答案是 `3`，对应 `wke` 或 `kew`。
空串答案为 `0`；空格、标点、大小写字母都作为字符参与判断。

## 当前实现的思路

用闭区间 `[left, right]` 表示当前窗口，并保持窗口内没有重复字符。
右指针 `right` 从左到右扫描；遇到窗口内已有的字符时，将左边界直接跳到旧位置之后。

| 变量 | 含义 |
| --- | --- |
| `last[c]` | 字符 `c` 最近一次出现的下标；处理当前字符前，记录的是此前的位置 |
| `left` | 当前无重复窗口的左边界，只向右移动 |
| `right` | 当前处理的字符下标 |
| `length` | 扫描过程中出现过的最大窗口长度 |

处理 `c = s[right]` 时：

1. 检查 `last` 中是否存在 `c`，并判断旧位置是否满足 `last[c] >= left`。
2. 如果旧位置仍在窗口中，令 `left = last[c] + 1`，排除上一次出现的 `c`。
3. 用 `right - left + 1` 更新最大长度 `length`。
4. 记录 `last[c] = right`，供后续字符查询。

哈希表可以保留窗口外字符的历史位置，无须随着左边界移动而删除。
是否位于当前窗口内，由 `last[c] >= left` 判断。

## 为什么左边界不能后退

字符串 `abba` 能体现 `last[c] >= left` 的必要性：

| `right` | 当前字符 | 此前最近位置 | 处理后的 `left` | 当前窗口 | 最大长度 |
| --- | --- | --- | --- | --- | --- |
| 0 | `a` | 不存在 | 0 | `a` | 1 |
| 1 | `b` | 不存在 | 0 | `ab` | 2 |
| 2 | `b` | 1，在窗口内 | 2 | `b` | 2 |
| 3 | `a` | 0，在窗口外 | 2 | `ba` | 2 |

最后一个 `a` 的旧位置为 `0`，已经不在当前窗口中，因此无需移动 `left`。
如果只检查字符曾经出现过，就把 `left` 改成 `0 + 1 = 1`，会得到含重复字符的 `bba`，错误地计算长度为 `3`。

移动前的窗口没有重复字符，所以加入当前字符时，只可能产生与当前字符有关的重复。
将左边界跳到它的旧位置之后，就能恢复窗口内无重复的性质。
每一步都记录以当前 `right` 结尾的最长合法窗口，取最大值即可得到答案。

## 当前 `while` 写法

代码使用 `while (last.count(c) && last[c] >= left)` 更新左边界。
一旦进入循环，执行 `left = last[c] + 1` 后，条件 `last[c] >= left` 立即变为假。
循环体内没有修改 `last[c]`，所以每次处理字符时，这个循环最多执行一次。

当前写法是正确的，也可以用 `if` 表达同样的逻辑。
`last.count(c)` 同时利用短路求值，避免查询不存在的字符时由 `last[c]` 插入默认值。
最近位置必须在检查重复之后更新，否则会把当前字符自身误认为此前的重复位置。

## 复杂度与字符范围

- 时间复杂度：哈希表查询、更新平均为 `O(1)`，总时间期望为 `O(n)`；极端哈希冲突下可能退化。
- 哈希表辅助空间：`O(min(n, 字符集大小))`，每种已出现的字符只存一个最近位置。
- 当前函数参数为 `string s`，按值传递；现有测例以字符串左值调用，会额外复制字符串，产生 `O(n)` 时间和空间开销。
- 因此，计入参数副本后的额外空间为 `O(n)`；单独分析算法数据结构时使用上述哈希表空间界限。
- 当前按 `std::string` 的 `char` 单元处理；对 UTF-8 中文等多字节文本，得到的是字节层面的结果。
