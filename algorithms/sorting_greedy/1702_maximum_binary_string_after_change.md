# 1702. 修改后的最大二进制字符串

- 算法分类：贪心。
- 数据结构：字符串、计数变量。
- 对应代码：[1702_maximum_binary_string_after_change.cpp](./1702_maximum_binary_string_after_change.cpp)。
- 练习状态：`maximumBinaryString` 已完成，12 组固定测例全部通过。

## 题意

给定只包含 `'0'` 和 `'1'` 的字符串，在题目规定的操作下得到字典序最大的二进制字符串。
题目允许反复使用相邻变换：`"00"` 可以变成 `"10"`，`"10"` 可以变成 `"01"`。
这两种操作都保持 `0` 的总数不变，但可以把零向右集中。

## 贪心结论

设第一个 `'0'` 的下标为 `firstZero`，字符串中 `'0'` 的总数为 `zeroCount`。
所有能移动的零都应尽量向右集中，最终最多只保留一个 `'0'` 位于：

`zeroPosition = firstZero + zeroCount - 1`

其余位置全部变成 `'1'`。如果没有 `'0'`，原字符串已经是答案；全零字符串也会按 `"00" -> "10"` 逐步改善。

## 为什么这样最优

字典序比较优先看靠左位置，因此每次操作都应优先把更靠左的 `0` 变成 `1`。
一个零变成一后，必须在相邻位置保留一个零作为代价；把这个代价零继续向右安排不会损失更靠左的位。
重复操作直到不能继续，所有可改善的前缀位置都成为 `1`，零的总数只留下一个集中位置，得到字典序最大结果。

## 实现方式

可以先扫描字符串，统计 `zeroCount` 和 `firstZero`，再把结果初始化为全 `'1'`，最后将 `zeroPosition` 设为 `'0'`。
也可以边扫描边记录第一个零和数量，避免模拟每一次操作；不需要真的执行操作序列。

## 边界与易错点

- 没有 `'0'` 时应原样返回全一字符串。
- 只有一个 `'0'` 时它不能凭空消失，结果与原字符串相同。
- 关键位置是第一个零加上零数量减一，不是最后一个零的原位置。
- 两种操作都要求相邻模式，不能把零的总数改成 `0`；最终至少保留一个零。
- 字典序最大意味着优先让更靠左的位置变成 `'1'`，不能只最大化某个局部片段。
- 返回结果长度必须与输入相同，零的总数也保持不变。

## 复杂度

- 时间复杂度：`O(n)`，扫描和构造结果各至多遍历一次字符串。
- 辅助空间复杂度：`O(n)`，返回结果字符串本身需要线性空间；若允许原地修改，可将额外工作变量降为 `O(1)`。
- 入口参数按值传递，调用时会产生输入副本；固定测例中的输入规模很小。
