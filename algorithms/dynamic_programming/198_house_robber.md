# 198. 打家劫舍

- 算法分类：动态规划。
- 数据结构：状态数组，或保存最近两项的滚动变量。
- 对应代码：[198_house_robber.cpp](./198_house_robber.cpp)。
- 练习状态：`rob` 已完成，12 组固定测例全部通过。

## 题意

沿街每间房屋藏有 `nums[i]` 的现金，相邻两间装有联动报警装置，同一晚偷了相邻两家就会触发。
求在不触发报警的前提下，一晚能偷到的最高金额。

约束：`1 <= nums.length <= 100`，`0 <= nums[i] <= 400`。

## 动态规划状态

令 `dp[i]` 表示只考虑前 `i` 间房屋（下标 `0..i-1`）时能偷到的最大金额。
对第 `i` 间房（下标 `i-1`）只有两种决策：

- 不偷它，收益就是前 `i-1` 间的最优解 `dp[i - 1]`；
- 偷它，那么第 `i-1` 间不能偷，收益是 `dp[i - 2] + nums[i - 1]`。

两者取较大值：`dp[i] = max(dp[i - 1], dp[i - 2] + nums[i - 1])`。
基础状态 `dp[0] = 0`（没有房屋）、`dp[1] = nums[0]`，答案为 `dp[n]`。

也可以让 `dp[i]` 表示「偷到下标 `i` 为止」的最优解，转移写成
`dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])`，初值 `dp[0] = nums[0]`、
`dp[1] = max(nums[0], nums[1])`。两种定义都对，但下标含义不能混用，混用是最常见的出错点。

## 滚动变量

转移只依赖前两项，不必保留完整数组。用两个变量 `prev2`（`dp[i-2]`）、`prev1`（`dp[i-1]`）：

```
cur = max(prev1, prev2 + nums[i]);
prev2 = prev1;
prev1 = cur;
```

初始化 `prev2 = 0`、`prev1 = 0`，从下标 `0` 遍历到末尾，最后返回 `prev1`。
这种初值下不需要对 `n == 1`、`n == 2` 特判，写起来最省心。

## 与 70 题的关系

递推形状和 [70. 爬楼梯](./070_climbing_stairs.md) 一样都只依赖前两项，
但那题是计数用加法，这题是最优化用 `max`，且带上了 `nums[i]` 的权重。
不要把 `max` 写成加法，那会变成「全都偷」。

## 边界与易错点

- `dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])` 里第二项加的是 `dp[i-2]` 而不是 `dp[i-1]`，加错就允许了偷相邻。
- 若用 `dp[i]` 表示「到下标 `i` 为止」，必须初始化 `dp[1] = max(nums[0], nums[1])`，写成 `nums[1]` 会漏掉只偷第一家更优的情况（如 `[2,1]`）。
- 用完整数组时 `n == 1` 会访问 `dp[1]` 越界，需要提前返回；改用 `prev2/prev1` 从 0 开始滚动可以规避。
- 不是「隔一家偷一家」的固定间隔。`[2,1,1,2]` 的答案是偷首尾得 `4`，中间隔了两家。
- 不能贪心地每次选当前最大值。`[1,3,1,3,100]` 贪心先拿 `100` 之后还能拿 `3+3`，但先拿 `3` 就会错过更优组合，必须靠 DP 全局权衡。
- 金额可以为 `0`，全零输入返回 `0` 是正常结果，不需要特殊处理。

## 复杂度

- 时间复杂度：`O(n)`，每间房屋只决策一次。
- 空间复杂度：完整状态数组 `O(n)`；滚动变量 `O(1)`。
