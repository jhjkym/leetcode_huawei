# 93. 复原 IP 地址

- 数据结构：路径段数组、字符串。

## 背诵四步

```cpp
bool isValid(const string& seg) {
    if (seg.empty() || seg.size() > 3) return false;
    if (seg.size() > 1 && seg[0] == '0') return false;   // 前导零
    return stoi(seg) <= 255;
}

void backtracking(const string& s, int start, vector<string>& path,
                  vector<string>& ans) {
    if (path.size() == 4) {                    // 1. 出口
        if (start == (int)s.size())            //    段够了还得刚好用完
            ans.push_back(path[0]+"."+path[1]+"."+path[2]+"."+path[3]);
        return;
    }
    for (int len = 1; len <= 3; ++len) {       // 2. 枚举本段长度
        if (start + len > (int)s.size()) break;
        string seg = s.substr(start, len);
        if (!isValid(seg)) continue;           // 3. 非法段跳过（continue 不是 break）
        path.push_back(seg);                   // 4. 选择 -> 递归 -> 撤销
        backtracking(s, start + len, path, ans);
        path.pop_back();
    }
}
```

口诀：**满 4 段且用完字符才收 → 枚举长度 1~3 → isValid 查前导零和 255 → push/递归/pop**。

## 题意

给定只含数字的字符串 `s`，在其中插入三个 `.` 把它分成四段，返回所有能组成的合法 IP 地址。
不能重新排序或删除字符，也不能添加数字。

合法 IP 段的定义：数值在 `0` 到 `255` 之间，且不含前导零（`0` 合法，`01` 和 `00` 不合法）。

约束：`1 <= s.length <= 20`，只含数字。

## 分割型回溯的思路

和 [46. 全排列](../backtracking/046_permutations.md) 同属回溯，但结构不同：
全排列每层选「哪个元素」，分割题每层选「这一段切多长」。

用 `start` 表示本段从哪里开始，每层枚举段长 `1`、`2`、`3`，切出的段合法就递归到 `start + len`。
递归深度固定为 4（四段），所以不需要 `used` 标记，靠 `path.size()` 判断切了几段。

## 出口的两个条件

这是本题最容易漏的地方。`path.size() == 4` 只说明切够了四段，
还必须 `start == s.size()` 才说明**刚好用完了所有字符**。

例如 `s = "25525511135"` 切出 `"2" "5" "5" "2"` 时已经四段，但后面还剩一串字符没用，
这是非法方案，必须 `return` 丢弃而不是收集。反过来，字符用完但不足四段时，
循环因 `start + len > s.size()` 自然 break，不会误收。

## isValid 的三查

- **长度**：`1` 到 `3`，由枚举范围保证，函数里再判一次更保险；
- **前导零**：`size() > 1 && seg[0] == '0'` 就非法。注意单个 `"0"` 是合法段，
  不能简单写成 `seg[0] == '0'` 就否掉，那样 `"0.0.0.0"` 会被漏掉；
- **数值**：`stoi(seg) <= 255`。因为长度已限制在 3 以内，最大 `"999"`，`stoi` 不会溢出。
  若不先限长度就调 `stoi`，超长串可能抛异常。

## 为什么用 continue 而不是 break

段非法时要 `continue` 试下一个长度，不能 `break` 整个循环。
以 `'0'` 开头时长度 1 的 `"0"` 合法、长度 2 的 `"01"` 非法；
而 `"256..."` 这类是长度 3 非法但长度 1、2 合法。两种方向都存在，
所以不同长度之间没有单调性，必须逐个试。

（严格说数值超 255 时更长的段只会更大，可以 break；但前导零的情况不满足单调性，
统一用 `continue` 最安全，也不影响复杂度。）

## 长度剪枝

四段每段最少 1 位、最多 3 位，所以合法输入的长度必须在 `[4, 12]` 内。
入口先判 `s.size() < 4 || s.size() > 12` 直接返回空，能省掉一整棵搜索树。
本题 `s.length <= 20`，这个剪枝很有效。

## 边界与易错点

- 出口只判 `path.size() == 4` 会收集到「四段没覆盖全串」的错误答案，必须同时判 `start == s.size()`。
- 前导零判断要保留单个 `"0"` 合法，写成 `seg[0] == '0'` 一律否掉会漏解（`"0000"` 的答案 `"0.0.0.0"` 就会丢）。
- `stoi` 前必须先限制段长，否则超长数字串会抛 `out_of_range`。
- 段非法用 `continue` 不用 `break`。
- 递归后要 `pop_back()` 撤销，漏掉会污染后续分支。
- 拼接时点号只有三个，写在段之间；用 `path[0]+"."+...` 最直观，不易多出尾部的点。
- `s.size()` 是 `size_t`，与 `int` 比较要显式转换，否则 `-Wall` 会报符号比较警告。

## 复杂度

- 时间复杂度：`O(3^4 · L)`，段数固定为 4、每段最多 3 种长度，是常数级搜索树；
  `L` 为拼接和校验字符串的开销。整体可视为 `O(1)` 规模。
- 空间复杂度：`O(1)` 辅助空间（递归深度固定 4，`path` 最多 4 段），不计输出。
