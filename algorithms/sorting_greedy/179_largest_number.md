# 179. 最大数

- 算法分类：贪心 + 自定义排序比较器。
- 数据结构：字符串数组。

## 背诵三步

```cpp
// 1. 转字符串
vector<string> strs;
for (int num : nums) strs.push_back(to_string(num));

// 2. 比拼接结果，不比本身；必须严格 >
//    写在 Solution 内时要加 static，才能当函数指针传给 sort
static bool cmp(const string& a, const string& b) {
    return a + b > b + a;
}
sort(strs.begin(), strs.end(), cmp);

// 3. 拼接 + 全零特判
string ans;
for (const string& s : strs) ans += s;
return ans[0] == '0' ? "0" : ans;
```

口诀：**转字符串 → 比 `a+b` 和 `b+a` → 拼完查前导零**。

## 题意

给定一组非负整数 `nums`，重新排列每个数的顺序（数字内部不能拆开），使拼接结果组成最大的整数。
结果可能非常大，需要返回字符串。

约束：`1 <= nums.length <= 100`，`0 <= nums[i] <= 1e9`。

## 思路

答案完全由「谁排在谁前面」决定，所以这是一个排序问题，关键是找对比较规则。

先把每个数转成字符串，再按下面的规则排序：对两个字符串 `a`、`b`，
如果 `a + b > b + a`（拼接后按字典序比较），说明 `a` 放前面更优，`a` 就排在 `b` 之前。

例如 `a = "3"`、`b = "30"`：`"330" > "303"`，所以 `3` 排在 `30` 前面，得到 `330`。
排序完成后按顺序拼接即为答案。

为什么不能直接按字典序降序排？`"3"` 和 `"30"` 字典序里 `"30" > "3"`，会得到 `303`，比 `330` 小。
也不能按数值降序排：`30 > 3` 同样给出错误的 `303`。必须比较拼接后的结果。

## 比较器的正确性

这个比较关系是**严格弱序**，可以安全交给 `sort`：

- 反对称：`a + b > b + a` 与 `b + a > a + b` 不会同时成立；
- 传递性：若 `a` 优于 `b`、`b` 优于 `c`，则 `a` 优于 `c`（两个等长拼接串比较等价于比较它们的数值，可由此推出）。

因为拼接后长度相同（都是 `|a| + |b|`），字符串字典序比较与数值比较在这里等价，
所以可以直接用 `>` 比较 `string`，不需要转成整数，也不会溢出。

写法上把比较器抽成具名函数 `cmp`，再 `sort(strs.begin(), strs.end(), cmp)` 即可。
写在类内需要加 `static`，否则成员函数带隐式 `this`，无法退化为 `sort` 需要的函数指针。
`a + b > b + a` 用严格大于保证相等元素返回 `false`，满足 `sort` 对比较器的要求。

## 前导零

全为 `0` 时（如 `[0, 0]`）排序拼接会得到 `"00"`，必须归一化为 `"0"`。
判断方式：排序后若首个字符是 `'0'`，则整个结果只能是零，直接返回 `"0"`。
注意 `[0, 0, 0, 1]` 的答案是 `"1000"`，不能因为含 `0` 就误判成零。

## 边界与易错点

- 比较器写成 `a > b`（直接比字符串）或按数值降序都是错的，必须比较 `a + b` 与 `b + a`。
- 比较器必须用严格 `>`，写成 `>=` 会破坏严格弱序，`sort` 可能越界导致未定义行为。
- 结果要用字符串返回，不能用 `long long` 承载，`100` 个 `1e9` 拼起来远超任何整型。
- 全零输入要特判返回 `"0"`，不是 `"00"` 或 `"000"`。
- 单元素输入直接返回该数的字符串，包含 `[10]` 这类多位数。
- 拼接时用 `string` 累加或预分配容量，不要在循环里反复构造临时对象。

## 复杂度

设 `n` 为元素个数，`L` 为数字字符串的最大长度（本题 `L <= 10`）。

- 时间复杂度：`O(n log n · L)`，排序 `O(n log n)` 次比较，每次比较拼接代价 `O(L)`。
- 空间复杂度：`O(n · L)`，存放字符串数组与结果。
